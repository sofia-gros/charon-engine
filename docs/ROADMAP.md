# Charon Engine ロードマップ

## 方針

Noita 寄りの機能 (液体・気体・反応・熱) を先に固める。これらはセル表現とシミュレータの中心に
関わり、後から変えるコストが最も高い。Terraria 寄りの機能 (広いワールド、建築、マルチプレイ)
は、その土台の上に後から追加する。

## 設計原則

FallingSandEngine の問題点に、それぞれ対応させている。

| 原則 | 内容 | 対応する問題 |
|---|---|---|
| セルは小さな POD | 1 セル 8 バイト以下の `Copy` 型。材質は `u16` の ID で、性質は材質テーブルから引く | `Arc<String>` を含む約 32 バイトのピクセルを毎回 clone していた |
| 材質と反応はデータ | 材質・反応を RON ファイルで定義し、コードの変更なしに追加できる | 材質がハードコードで、性質を持つ場所がなかった |
| 決定的 | 乱数はシード・座標・tick から導出する。結果はスレッド数に依存しない | チャンクごとに無シードの乱数を生成していた |
| 安全な並列化 | `unsafe` は既定で禁止。必要な箇所は小さなモジュールに閉じ込め、Miri で検証する | `unsafe` 116 箇所、作者自身が UB を認めていた |
| 核はヘッドレス | `charon-core` は描画・ウィンドウに依存しない。ゲーム固有のコードは入れない | エンジンとゲームが分離していなかった |
| チャンクは 2 の冪 | 64×64。座標変換をシフトとマスクで行う | `CHUNK_SIZE = 100` で除算と剰余が最内ループにあった |
| 最初からテスト | 決定性を利用したスナップショットテストとベンチマークを各マイルストーンで追加する | 19,000 行にテスト 7 個 |
| 移植性のある描画 | wgpu を使い、macOS と Web を切り捨てない | OpenGL 4.3 必須だった |

## マイルストーン

各マイルストーンは「完了条件」を満たしたら次へ進む。

### M0 環境整備 (完了)

- Cargo ワークスペース、最新 stable の固定、lint 設定、CI (fmt / clippy / 3 OS でテスト)

### M1 シミュレーション核 (シングルスレッド)

- `Cell` 型の確定。初期案は 8 バイト:
  `material: u16` / `flags: u8` / `shade: u8` (色のばらつき) / `temperature: i16` / `aux: u16` (寿命など)。
  ベンチマークを取って確定する
- 材質テーブルと RON からの読み込み (密度、相、色、粘性など)
- 64×64 チャンクと固定サイズのワールド、座標型
- 決定的な乱数
- 粉体・液体・気体・固体の移動規則。密度差による入れ替わり (水に砂が沈む、油が水に浮く)
- **完了条件**: 同じシードで同じ結果になるスナップショットテストが通る。
  質量保存 (セルが消えたり増えたりしない) のプロパティテストが通る

### M2 反応と熱

- 反応テーブル (材質 A + 材質 B → 生成物、確率つき)。ID の組で O(1) に引く
- 温度の拡散、相変化 (氷 ↔ 水 ↔ 蒸気、溶岩 ↔ 岩)
- 火、燃焼、寿命つきセル (煙、火花)
- **完了条件**: 「水 + 溶岩 → 岩 + 蒸気」「木が燃えて煙になる」などの代表的な反応が
  データ定義だけで再現でき、スナップショットテストが通る

### M3 並列化と性能

- 4 フェーズの市松更新。チャンクの借用を安全に分割する
- dirty rect による休眠 (変化のない領域を処理しない)
- criterion によるベンチマーク
- **完了条件**: 1 スレッドと N スレッドで結果が完全に一致する。
  `unsafe` を使った場合は Miri が通る。目標性能 (M1 のベンチ結果を基に設定) を満たす

### M4 ビューア (サンドボックス)

- wgpu + winit + egui のサンドボックスアプリ (`apps/sandbox`)
- ブラシでの材質配置、一時停止とコマ送り、デバッグ表示 (チャンク境界、dirty rect、温度)
- **完了条件**: 手で触って M1〜M3 の挙動を確認できる

### M5 無限ワールドと保存

- チャンクの読み込み・退避、非同期のワールド生成
- 保存形式 (バージョンつき、パレット化 + 圧縮)。材質 ID の変更に耐える
- **完了条件**: 遠くまで移動して戻っても状態が保たれる。古い保存データを読める移行テストがある

### M6 剛体とパーティクル

- 剛体 (rapier2d)、輪郭抽出によるコライダー生成、破壊による分割
- 高速に動くセルのパーティクル化と着地
- **完了条件**: 剛体が液体に浮き沈みし、破壊で分かれる。決定性が保たれる

### M7 ライティング

- wgpu のコンピュートシェーダーによる RGB ライティング。発光する材質
- **完了条件**: Windows / Linux / macOS で同じ見た目になる

### M8 ゲーム層 (Terraria 寄りの機能)

- エンティティ、プレイヤー、当たり判定
- バイオームと構造物のワールド生成
- 背景レイヤー、建築
- MOD とスクリプト
- マルチプレイ (決定性を前提に設計する)

M8 は範囲が広いため、M4 が終わった時点で分割して計画し直す。

## 予定しているクレート構成

必要になった時点で作る。空のクレートは先に作らない。

| クレート | 役割 | 追加時期 |
|---|---|---|
| `charon-core` | セル、材質、チャンク、シミュレーション | M0 |
| `apps/sandbox` | ビューア | M4 |
| `charon-render` | wgpu による描画 | M4 |
| `charon-world` | 無限ワールド、保存、生成 | M5 |
| `charon-physics` | 剛体、パーティクル | M6 |
