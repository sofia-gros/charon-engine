## 1. 製品像

**「落ちる砂の物理を持つ、Terraria 型の 2D サンドボックス」**。Android (主) と Windows (従) で遊ぶ。

- 世界はすべてセル (1 画素) でできていて、砂は崩れ、水は流れ、火は燃え広がる。
- 建築物 (拠点・ダンジョン) は、8×8 セルの**ブロック**でできている。プレイヤーは Terraria のように建築できる。
- 掘る・集める・作る・建てる・探索する・装備を整える・敵と戦う、のループを、スマホの片手と両手の操作で遊べる。

**製品として成立する最小のプレイ体験 (これを満たしたら「製品版」)**: 1〜2 時間の通しプレイで、次が一通りできる。

1. 始まりの地表で、掘って素材を集め、ブロックを作って小さな拠点を建てる。
2. 洞窟へ潜り、鉱石と宝箱を見つけ、装備 (武器・防具) を作る・拾う。
3. 敵 (杖持ちの魔法使いを含む) と戦う。炎・毒などの状態異常が絡む。
4. 構造物 (ダンジョン) を探索して、ボスを倒す。
5. 保存して終了し、再開できる。端末が変わっても、設定を失わない。

**やらないこと (今回の製品版の範囲外)**: オンラインの対戦・マッチング、課金、世界のエディタ (外部ツール)、3D。

## 2. 決定済みの設計 (ブロックと建築)

### 2.1 用語

| 用語 | 意味 |
|---|---|
| セル | 世界の 1 マス = 1 画素。物理の本体。 |
| ブロック | 8×8 の格子に揃った **64 セルのかたまり**。建築の単位。セルより**上位**。 |
| アイテム | 持ち物に入るもの (材質の粉・ブロック・武器・防具・消耗品・素材)。 |

### 2.2 【決定】ブロックの仕組み

1. **世界はすべてセル。** 建築物 (拠点・ダンジョン) だけが、ブロックでできる。
2. **ブロックは、セルの旗 (`FLAG_BLOCK`、`flags` の最後の 1 ビット) で表す。** 別のブロックの表は持たない。保存は、今のチャンクの保存形式のまま。ブロックの種類 = 材質 (砂のブロック = 旗の付いた砂)。
3. `FLAG_BLOCK` のセルは、材質が粉でも**動かない** (剛体 `FLAG_BODY` と同じ扱い)。これが「ブロックが上位」の意味。
4. **ブロックが崩れる規則**: ブロックの中の隣のセル (同じ 8×8 の中) が空いたら、そのセルの旗を外す。旗が外れたセルは普通のセルに戻る (砂なら粉になって崩れ、石なら固体のまま残る)。同じ 8×8 の中だけで判定するので、隣のブロックには連鎖しない。座標から決まるので、決定的。
5. **つるはしでブロックを丸ごと壊すと、ブロック 1 個**がアイテムで返る。一部だけ壊れたら、残りが普通のセルになって、セルのアイテムとして拾える。

### 2.3 【決定】ブロックを置く規則 (押し出し)

- ブロックは 8×8 の格子に揃えて置く。すでにブロックがある場所には置けない。
- 置く場所にあったセルは、**消えずに外へ押し出される** (セルの数は変わらない)。
- **押し出す向きの優先順位**は、セルの位置から見て次のとおり (幅 8 は偶数なので、半分ずつで迷いがない)。
  1. 左右: ブロックの左半分のセルは左へ、右半分のセルは右へ。
  2. 左右が塞がっていれば、上下: 上半分は上へ、下半分は下へ。
  3. 上下左右がすべて塞がっていれば、上下左右でいちばん近い空きへ。
- **押し出しは「行 (列) を押す」動き**にする。左へ押す k 個のセルは、その行の左側を探して、空きが合計 k 個になる位置までの範囲を、順番を変えずに、ブロックの左端に詰め直す。砂場は、ブルドーザーに押されたように全体がずれる (「砂場全体が動く」)。押し出したセルには落下の旗を立てて、周りを起こす。
- **敵・プレイヤーが置く場所にいたら**、左右の、いちばん近いブロックの外へ飛ばされる (左右が塞がっていれば、上下)。
- 置けない場合 (操作は何も変えずに失敗する):
  - 置く場所に**固体** (岩の地形・ほかのブロック) がある。先に掘る。押し出すのは、空・粉・液体・気体と、敵・プレイヤーだけ。
  - 敵・プレイヤーの押し出し先が、どこにもない (潰して倒す、にはしない)。
- 置く・壊すは、セルの更新の外で行う**操作**で、同期 (Lockstep) の入力に載せる (通信の版を上げてコマンドを足す)。

### 2.4 【決定】集める・作る

- 粉セルを壊すと、**粉のアイテム**が拾える。**64 個 = 1 ブロック**にクラフトできる。すべての材質で同じ (石のセルをレーザーで掘ったものでも作れる)。液体は集められない (バケツは後)。
- ブロックは、置く前は 1 個のアイテム、置いたら 64 セルになる。

### 2.5 【決定】そのほか (10 項目)

1. 複数の武器と防具。
2. 複数のエフェクト (敵の杖持ちの魔法でファイアーボールが飛び、炎が延焼してプレイヤーにかかる、など)。
3. 洞窟の抜本的な作り直しと、広いワールド。
4. 8×8 セルのブロックと、Terraria のような建築 (上のとおり)。
5. スマホでも快適に建築できる操作 (Android 版 Terraria を参考にする)。
6. プレイヤーと敵を大きく (2 ブロック幅)。
7. 乗り越えは 1 ブロックまで自動。2 ブロックは引っかかる。
8. ジャンプ力が強すぎるので下げる。
9. 敵の自動スポーンと、チャンク外の敵の削除。
10. プレイヤーと敵のインベントリ。敵は、持ち物のいちばん強い装備を自動で装備する (拾った装備で戦えるので、戦闘に自由度が出る)。

## 4. 段階 (フェーズ) と依存関係

依存の向き: **ブロック → アイテム → 体の大きさ → 建築の操作 → 戦闘 → ワールド・敵 → 仕上げ**。それぞれの終わりで、実機で触ってもらう。

| フェーズ | 内容 | 終わりの条件 |
|---|---|---|
| **M19 ブロック** | 仕様 (`17-blocks.md`)、`FLAG_BLOCK`・崩れの規則・押し出し、設置・破壊の操作、通信のコマンド | §2 の規則が、ヘッドレスのテストですべて確かめられる。ゲームには、置く・壊すだけの最小の操作 |
| **M20 アイテム** | データ駆動のアイテム、持ち物の作り直し、ホットバー、クラフト、装備スロット、保存の版を上げる | 64 粉 → ブロック、素材 → 装備、保存・復帰 |
| **M21 体の大きさと移動** | プレイヤー・敵を大きく (16×24)、速度・重力・ジャンプ・乗り越え (1 ブロック) の調整、カメラ | 実機で、新しい体の動きが気持ちよい。テストの前提を新しい体に合わせる |
| **M22 建築の操作** | スマホ・PC の建築操作、クラフト・インベントリ・装備の画面、チュートリアルの最初の部分 | スマホで、片手・両手とも、拠点が建てられる (実機の確認) |
| **M23 戦闘** | 複数の武器、防具・耐性、ダメージの種類、ノックバック、エフェクト (パーティクル・動く光)、ファイアーボールの一連 | 杖持ちの敵と戦って、燃えて、防具で変わる |
| **M24 ワールド** | 洞窟・層・バイオーム・鉱石・池の作り直し、構造物・ダンジョン、広さ、熱が眠る | 広い洞窟を、実機で止まらずに探索できる |
| **M25 敵とボス** | 自動スポーン・削除、敵の種類、経路探索、敵の持ち物と自動装備、ボス | 通しプレイで、敵が適度に出て、ボスを倒せる |
| **M26 仕上げと配布** | BGM・効果音、日本語、設定、死亡と復活、実績ではなく基本のヒント、性能の調整、署名つきの配布、権利の確認 | 「最小のプレイ体験」が 1〜2 時間通しで遊べる。実機の性能の目標を満たす |

並行してよいもの: 音の素材の準備・権利の確認、日本語の文言の整理、画面のデザイン (どのフェーズでも)。

## 5. 主なリスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **体を 3 倍にすると、テストの多くが書き直しになる** (5×10 の前提) | 大きな手戻り | 体の大きさを定数に集めてから変える。期待値の変更は、仕様の変更として記録する (「何が起きるべきか」は変えない) |
| 広い洞窟で、更新するセルが増え、実機が重くなる | 遊べない | 更新距離の設定、熱が眠る変更 (K)、洞窟の設計で空洞の大きさを制限、実機で早めに計測 |
| 押し出しで、巨大な砂場を押すと重い・挙動が不自然 | 建築の体験 | 行・列の長さの上限、押せないときは置けない。実機とヘッドレスで確かめる |
| ブロックの旗が、保存・描画・掘る道具・火・酸との相互作用で、想定外を生む | バグ | 仕様に「旗を見る場所」の一覧を書き、各所にテスト |
| スマホの建築操作が、実機で窮屈 | 製品の核心 | 早い段階 (M19 のあと) に試作して、実機で何度も直す |
| 音・フォント・画像の権利 | 公開できない | 素材の一覧と権利の表を作る。生成した音・自作の素材を優先 |
| 同期 (Lockstep) の入力の拡張 (ブロックの操作) | 通信の非互換 | 通信の版を上げる。協力プレイは P2 なので、今のうちに設計だけ合わせる |
| 実機のテストが私にはできない | 見落とし | 各フェーズの終わりに、実機での確認の項目を渡し、結果をもらう (今までどおり) |

## 6. 精査してほしい点 (未決定のもの)

1. **体の高さ**: 2×3 ブロック (16×24 セル) でよいか。
2. **ジャンプの高さ**: 3〜4 ブロックを目安にしてよいか (実機で調整する前提)。
3. **掘る道具**: つるはし (ブロック単位) を基本に、レーザー (円形に削る) は特別な道具として残す、でよいか。
4. **最初のブロックの種類**: 土・石・砂・木・ガラス・レンガでよいか。
5. **ワールド**: 横は無限、縦は深さに上限 (底の層で止まる)、でよいか。
6. **敵の保存**: 敵は保存せず、スポーンで作り直す案でよいか (ボスの撃破だけ保存)。
7. **死亡時**: 持ち物を落とす・お金を失う・何も失わない、のどれにするか。
8. **P2 の扱い**: 昼夜・NPC・店・協力プレイ・実績は、今回の製品版から外してよいか。
9. **対応端末の基準**: 「中位の Android」とは、具体的にどの端末・どの性能か (実機はお持ちのものを基準にする、でよいか)。
10. **配布先**: Google Play か、直接配布 (GitHub の Releases) か。ストアなら P1 の項目が P0 になる。
11. **言語**: 日本語と英語の両方か、日本語だけか。
12. **素材の方針**: 音・フォント・画像は、自作・生成・フリー素材のどれを使うか。

## 7. 付録: 今までに実装済みのもの (製品に使える土台)

- **シミュレーション**: 粉・液体・気体・反応・熱・燃焼・寿命、休眠、更新距離 (コールドフリーズ)、決定性、並列化。
- **世界**: 無限のチャンク、保存・復帰、洞窟 (狭い)、背景レイヤー。
- **物理**: 剛体・ロープ・パーティクルの土台。
- **ゲーム層**: プレイヤー (移動・段差・コヨーテタイム・ジャンプの先行入力)、体力・息・マナ、状態異常、浮遊、飛び道具、杖と呪文、敵 (2 種)、ワイヤーフック、掘る道具、ドロップ、持ち物、崩落、出来事、同期 (Lockstep)。
- **入口**: `Game` トレイト、アセット、スクリプト (Rhai)、MOD、設定、安定した API。
- **描画・画面**: wgpu、光 (4 段階)、スプライト・アニメーション、HUD、パネルの格納、タッチ操作 (移動パッド・ポインター・ボタン・ズーム)。
- **音**: ミキサー、効果音、デバイス出力。
- **配布**: Windows の zip と Android の APK を、タグで自動ビルド。
