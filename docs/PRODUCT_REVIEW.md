# 製品ゲームに向けた不足・改善点・性能の報告 (v0.0.7 の時点)

M19〜M27 までを実装・自動テストした状態での、製品として足りないもの、直すべき点、性能の改善策。**実機 (ウィンドウ・Android) での通しの確認は、まだ一度もしていない**ので、最優先はそれ (§1)。

## 1. 最優先: 実機の確認 (リリースの品質を決める)

| 確認 | 理由 |
|---|---|
| Windows のウィンドウで通しプレイ (歩く・跳ぶ・置く・壊す・戦う・復活) | M19 以降は、自動テストと GPU の描画テストまで。操作の感触 (体の大きさ・速さ・ジャンプ・段差) は、人が触らないと決まらない |
| Android 実機のタッチ (仕様 18) | 固定スティック・使うボタン・フックのスティック・ホットバーの大きさと位置は、仕様どおりに作っただけ。指の大きさ・誤タッチは実機で調整 |
| 範囲の外の液体の落下 (M27) | 画面から離れた水が実際に落ち続けるか。落ちた水が画面に入ったとき不自然に見えないか |
| 音 | 生成した効果音が実際に聞こえるか (cpal の出力は未確認のまま) |
| 冒険の世界の景色 | 砂漠の砂丘が急な崖になる、土の層が薄い、背景がない、など。スクリーンショット (`docs/screenshots/M26-adventure.png`) では、地形はつながるが、見た目の作り込みは足りない |

## 2. 製品として足りない機能

**ゲームの骨格**
- **セーブの完成**: プレイヤーの持ち物・装備・ホットバーは `PlayerSave` に入れたが、`GameSave::with_items`/`apply_items` を App の保存・復帰の経路につないでいない (つなぐのは短い作業)。ブロックの旗 (`FLAG_BLOCK`) の保存は、チャンクで往復することをテスト済み。ワールドの保存形式の版管理・古いセーブの移行方針が要る。
- **チュートリアル / 目標**: 今は最初の 25 秒のヒントだけ。「木を集める → 作業台 → 道具 → 家 → 洞窟 → ボス」の流れを示す進行表示が要る。
- **昼夜・天候・時刻**: 空の色・光の変化がない (Terraria 型では雰囲気の中心)。
- **作業台・かまど・箱 (収納)**: クラフトのレシピに作業台の指定 (`station`) はあるが、作業台のブロックと「近くにあるか」の判定は、置いたブロックの種類を見るだけ。収納 (箱)・看板・ドア・はしごなどの「置ける機能ブロック」がない。
- **ブロックの種類と加工**: 木・石の壁 (背景に置く壁)、松明 (光るブロック)、水・溶岩のバケツ。背景の壁がないと、家を建てても外と同じ暗さになる。
- **NPC・店・通貨**: 村人・取引はない。敵の戦利品も材質のセルだけで、アイテム (ポーション・装備) を落とせない (`Drops` が材質専用のため)。
- **アイテムの拡張**: レア度・修飾・耐久・スタックの上限を種類ごとに変える、弾薬 (矢の消費)、投げもの、アクセサリーの能力 (二段ジャンプなど)。
- **敵の知能**: 経路探索がない (壁・段差に当たったら跳ぶだけ)。飛ぶ敵・水中の敵・穴掘りの敵・群れ・イベント (夜の襲撃) がない。ボスは拳で殴るだけで、専用の行動 (突進・弾幕・呼び出し・段階) がない。
- **難易度・バランス**: 体力・ダメージ・ドロップ率・出現率は仮の数値。通しプレイで調整するための、数値を一か所で変えられる設定が要る。
- **マルチプレイ**: Lockstep の土台とホスト中継はあるが、アプリへ組み込んでいない。ブロックの置く・壊す・アイテム・装備のコマンド (T19.5、プロトコルの版を 4→5) が未実装。

**UI / 体験**
- **日本語の文字**: egui の既定フォントに日本語がなく、画面は英語。日本語フォントの同梱 (ライセンス確認つき) と、文字列の外出し (多言語) が要る。
- **アクセシビリティ**: 色覚への配慮、UI の大きさ (設定あり)、操作の再割り当て (キーはあり、タッチはなし)、ゲームパッドでのメニュー操作。
- **ホットバー・持ち物の画面の作り込み**: 今は仮の色の四角。アイコン (自作)・ドラッグでの並べ替え・個数の分割・クイックスタックが要る。体力・マナはバーのまま (仕様 18 のハート・星は未)。
- **ポーズ・設定・タイトル画面**: タイトル (新規・続き・設定)、ワールドの選択、難易度、音量は一部ある。
- **オーディオ**: BGM (バイオーム・ボス)、足音・環境音、空間音 (距離で小さくする)。生成した効果音は仮。

**配布・運用**
- **署名つきの配布**: Windows (コード署名)・Android (リリース署名の鍵の管理)。今は zip と apk のビルドのみ。ストア向けのアイコン・説明文・年齢区分。
- **アセットの権利**: 今の絵・音は自作・生成のみのはずだが、同梱物の一覧と権利の確認 (フォントを足すときは特に) を文書にする。
- **クラッシュ報告・ログ**: パニック時のログ保存、設定画面からのログの書き出し。
- **更新・Mod**: MOD の読み込み (RON・Rhai スクリプト) はある。MOD の一覧・有効化の画面、MOD 用の文書 (GAME_API) の更新 (M19〜M27 の API が未反映)。

## 3. 改善点 (品質・保守)

- **仕様と実装のずれの掃除**: 仕様 10 の一部 (体の大きさ 5×10 の前提など) が古い。ROADMAP・STATUS・GAME_API を M27 の状態に合わせる。
- **テストの前提**: M21 で多くのテストの座標を書き換えた。座標の直書きが多いので、テスト用の「床の上にプレイヤーを立たせる」補助を `testkit` に集めると、次の変更が楽になる。
- **GameInput の拡張**: フックの巻き取りを張りっぱなし (自動で巻く) にした。Terraria と同じだが、振り子の操作をしたいなら、巻き取りを分ける入力が要る (通信の版を上げる機会にまとめる)。
- **`GameState` の肥大**: `game.rs` が大きい。敵・武器・フック・掘る道具を、それぞれ別ファイル (`combat.rs` のように) に出していく。
- **Clippy の `too_many_arguments` の許可**: `ProjectileWorld::spawn` や `draw_hotbar` など。引数を構造体にまとめる。
- **App の `lib.rs` (約 2,000 行)**: 入力・カメラ・保存・描画が一つに集まっている。`build_input.rs` のように、分けていく。

## 4. 性能の改善策

現状の実測: 100 万セル / 1 tick で約 35〜41 ms (目標 8 ms は未達)。冒険の世界の生成は、画面のまわり 165 チャンクで約 0.8 秒 (1 チャンク約 5 ms)。溶岩の池は、毎 tick 約 1,500 セルを更新し続ける。

1. **溶岩の熱を眠らせる** (最優先の改善、持ち主の確認待ち): 熱の更新に「差が小さければ書かない」しきい値を入れて、温度が落ち着いたセルを休眠させる。シミュレーションの結果が変わるので、仕様 03 に書いてから行う。深い洞窟 (溶岩の湖が底にある冒険の世界) では効果が大きい。
2. **コールドフリーズの粗い処理の最適化** (M27): いまは範囲の外の全セルを 4 tick ごとに走査している。チャンクごとに「液体・気体を含むか」のカウントを持てば、液体のないチャンクは走査を飛ばせる (`Chunk` に 1 つの数を足すだけ)。
3. **生成の並列化とキャッシュ**: `Streamer` の生成を別スレッドで先読みする (進行方向のチャンクを先に作る)。生成は純粋関数なので、そのまま並列にできる。デスクトップでは問題ないが、Android では移動中のカクつきの原因になりやすい。
4. **洞窟のノイズの計算量**: 1 セルあたりノイズを 6 回ほど評価している。深さが浅い (表面の層) と、洞窟がないと分かる列を先に捨てる、ノイズの粗い格子を使い回す (8×8 ごとに 1 回評価して補間)、などで数倍速くなる見込み。
5. **描画**: 光の計算 (xHigh) が重い。Android の既定は Low にし、設定で上げる。スプライト・剛体の描画は問題になっていない。
6. **シミュレーションの並列度**: `parallel` feature の 9 フェーズ更新は、チャンクが 3 つ離れているため、少ないチャンクだと並列度が出ない。更新するチャンクが 10 未満のときは直列にする判断 (スレッドの起動コストを避ける)。
7. **メモリ**: 1 セル 8 バイト。読み込みチャンクの数 (半径 3)・更新距離の設定で調整できる。Android では更新距離の既定を小さく (1〜2) して、バッテリーと熱を抑える。
8. **セーブの書き込み**: リージョンファイルの保存を、フレームの外 (別スレッド) で行い、保存中のカクつきを避ける。
9. **計測の整備**: `docs/BENCHMARKS.md` に、冒険の世界での 1 tick の時間 (更新するセルの数・チャンクの数)・フレーム時間の分布 (p95・p99) を、CI の記録として足す。目標 (8 ms) の対象を「画面のまわりの更新するセル」に絞り直す案もある (全 100 万セルは、製品では起きにくい)。

## 5. 提案する次の順番

1. 実機の通しプレイ (Windows → Android)。見つかった不具合を直す。
2. セーブの完成 (持ち物・装備・ホットバー・版管理)。
3. 溶岩の熱の休眠 (性能)。
4. 背景の壁・松明・作業台・箱 (建築の楽しさの中心)。
5. 敵の経路探索・飛ぶ敵・ボスの行動、バランス調整。
6. 日本語フォント・BGM・昼夜。
7. 署名つきの配布・権利の確認 → v0.1.0。
