# マテリアルとセル・粒子の物理

## 定義と挙動

MaterialDefは安定キー、基本定義、配置寸法、物性、挙動キー、反応、外観参照、作者schemaを持つ。物理のhot配列にはmass、抵抗、熱容量、伝導率、movement係数などを配置し、画像、音、説明文を分離する。

基本の挙動として静止固体、粉体、液体、気体を提供し、独自挙動も`MaterialBehavior`から登録できる。支持、移動、熱、反応、破砕、表現は独立した契約を持ち、基本定義と作者の明示指定から解決する。未対応の設定を無視して受け付けない。

| 物性 | 表現と接続先 |
| --- | --- |
| mass | 1占有cellの正の整数ゲーム質量。物質交換、慣性・浮力の換算、変換の収支 |
| 重力・抗力・浮力・摩擦 | 検証済みの係数。移動、物体と流体の連成、controller |
| 硬度・結合・anchor | 破壊、局所支持、剛体への切り出し。名前による特別扱いをしない |
| 衝突・透過 | group/maskと形状。物理衝突と画像alphaを区別 |
| 熱 | heat capacity、conductivity、phase family、latent heat、温度範囲 |
| 反応 | ignition、fuel、wet、接触rule、腐食等の処理keyと設定 |

物性の値域、単位、behavior別の意味はschemaへ定義し、登録時に検証する。温度・質量等の任意のSI物理と同一である保証はせず、エンジン単位と各solverの意味を公開する。

## 基準のセル移動

参照solverは単一の安定した走査で処理する。重力方向へ下から上、同一行はtickで左右を交互にする。粒子を動かした両端と、通過する予約cellを記録し、同じトークンをそのphaseで二度動かさない。

粉体は下、左右の斜め下、支持状態の順で候補を評価する。液体は下、圧力差による移動、左右の均しを行う。気体は温度と相対密度による上昇、圧力差、拡散を行う。各ruleは候補の順、読み書き半径、最大移動距離を宣言する。

移動速度は固定小数点のcell/tickと残差で扱い、距離が1cell未満でも蓄積する。複数cellの移動は途中をsweepし、壁やUnavailableを飛び越えない。既定の局所探索半径は8cell、これを超える操作は広域Job APIを使う。上限の変更はsim設定へ記録する。

移動は空きcellとの交換、またはmassと浮力の条件を満たす物質間交換として行う。CellCore、energy、timer、混合状態、instance参照を同時に移す。水流による押し退けなどの複数cell変換は、全宛先を予約してから確定する。

## 液体と気体の圧力

v1はcell占有と圧力proxyを使うゲーム用の流体モデルを採用する。Navier–Stokesの実在流体精度を要求するsolverにはしない。閉じた水路、サイフォンに相当する経路の押し上げ、ポンプ、気体の閉塞・排出を表現できることは必須とする。

これは標準providerの方針である。液量を持つtile流体、異なる解像度、別の移動順や数式が必要なら、[25](25_OPEN_EXTENSION_AND_COLLISION_CONTRACTS.md)のGridChannelとMaterialTransportを使う。満杯cellへの丸めや固定4反復を作者の再現処理へ強制しない。

active領域のfluid連結を読み取り、重力による深さと閉塞、温度に応じたgas pressure sourceからQ16の圧力場を固定4反復のJacobi更新で求める。前tick圧力と進行中の広域検索は保存する。圧力は熱energyとは別で、実在エネルギーの保存量として扱わない。

高圧側から低圧側への局所移動候補を作り、宛先を安定順で予約する。満杯領域を通した押し出しは経路をJobで検索し、空き先までの一連の交換を原子的に実行する。圧力値だけを理由に物質を生成・消失させない。非常に大きな連結領域は固定件数予算で進め、応答の遅れと進捗を診断へ公開する。

複数物質の溶液等は、種類と整数比率を持つ`MixtureState`として登録する。参照は安定順に正規化し、mix/separate ruleが入力と出力を予約する。異なる液体を無条件に混合する仕様にはしない。

## 熱と相変化

各物質はenthalpy familyを持ち、energyから温度とphase fractionを整数の区分関数で求める。固体・液体・気体の区間には熱容量、転移区間には潜熱を定義する。同じfamily内の変化ではenergyを保持し、materialとphase fractionを更新する。

隣接する各辺を一度だけ評価し、温度差と伝導率から整数fluxを計算する。fluxの上限はその辺の平衡移動量の1/8とし、四近傍から同時に流れても逆転・発散しないようにする。scratchへ等量を加減算し、全辺の評価後にcommitする。端数は辺の余剰accumulatorへ保存し、小さな温度差を恒久的に切り捨てない。

active/inactive境界は断熱とし、環境への放熱・外部からの加熱はsource/sinkの明示ruleとして台帳へ記録する。熱容量、伝導率、温度、積の上限を登録時に検証し、計算の中間値は`i128`を使う。

## 燃焼、濡れ、接触反応

ReactionDefは入力物質・状態・必要量、条件、出力物質・粒子・energy、消費timer、優先順位、instance移行ruleを持つ。接触pairと周辺条件から疎な索引で候補を検索し、rule keyと座標順で競合を解決する。

予約、条件の再確認、入力と出力の一括commitを一つの取引にする。出力の空間やpoolが不足する場合は入力、燃料、timerを消費せず延期する。燃焼出力を視覚だけにするか、物質として作るかは定義で選ぶ。

燃料・濡れ・腐食の進捗は個体sidecarへ保存する。反応で個体が変わる場合は、対応するcomponentを移行、drop、消費のいずれにするか宣言する。未定義の個体状態を黙って消さない。標準Deferredの連鎖は次tickへ送る。同tickで必要な反応は25のSameTickを指定し、その処理順と終了条件を保存する。

## 正規粒子と表示粒子

物質粒子はMaterialId、質量トークン数、位置・速度、energy、timer、個体状態、所属Worldを持つ。DDAまたはshape sweepで地形・物体との接触を検出し、着地時は出力cellを予約して再配置する。着地できない粒子は待機または運動状態で保持し、寿命だけで物質を消さない。

視覚粒子は表示サービスが所有し、寿命で消せる。品質設定や描画距離で削減でき、正規物理、damage、saveの整合を変えない。光や音の演出から逆に正規damageを推測しない。

## 保存する収支

material別のトークンと換算massを、世界cell、物質粒子、剛体local cell、退避領域、排除reservoirの合計で追跡する。移動や剛体への移行は合計を変えず、生成・消費・反応は理由付きの変換receiptを残す。

採掘してitemへ変換する場合など、異なる表現へ移す処理は変換ruleを明示する。すべてのrecipeに実在質量保存を強制するのではなく、作者が意図した発行・消費を検査可能にする。

cell表現の変更と理由付きreceiptを同時に保存する経路は[32](32_MATERIAL_RECEIPTS.md)を参照する。この経路だけで、rawな編集・生成器・全providerや粒子・剛体・退避領域を含む全表現の総量を集計済みとは判定しない。

## 独自挙動と最適化

独自ruleは読み取りstencil、候補作成、容量見積もり、commit、codec、sleep条件を登録する。汎用callbackを全cellで呼ぶ経路と、型別のbatch kernelを登録する経路を用意する。高負荷の挙動で後者が必要な理由をAPI資料に説明する。

palette圧縮、dirty更新、SIMD、候補評価の並列化は参照solverとのdifferential testに通す。別の結果を意図するsolverは別sim profileとし、最適化という名で正規挙動を変更しない。
