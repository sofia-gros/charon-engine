# 設定と拡張機能をどこで扱うか

## 配置を決める原則

設定の置き場所は、その値が何を決めるかで判断します。ウィンドウなどの具体例だけを固定の一覧にして、後から追加するエンジン設定を排除しません。

| 問い | 主に扱う場所 | 例 |
| --- | --- | --- |
| どの実装をビルドへ含めるか | Cargoの依存とfeature | 描画バックエンドの実装、追加の資産形式、外部の拡張クレート |
| 組み込まれたエンジンをどう実行するか | YAMLと型付きのエンジン設定API | 描画方式・品質、ウィンドウ、音響、資産ルート、キャッシュ、診断 |
| どの機能や処理をゲームへ導入するか | Rustの登録API | Scene、プラグイン、独自システム、素材、イベントハンドラー |
| 何をゲームに登場させ、どう動かすか | Rustの定義・生成・操作API | マテリアルのブロックサイズ、プレイヤーの構成、入力アクション、ゲーム規則 |

作者がゲーム固有のデータファイルを設けることもできます。そのデータは作者の読み込み処理から公開APIへ接続し、エンジンの設定ファイルと混同しません。

## YAMLはエンジンの実行設定を扱う

YAMLは、組み込まれた機能を実行する際の方針や既定値を保持します。領域と役割を以下に示し、v1のキー、型、既定値は末尾のschemaで定めます。

| 領域 | 設定として扱う内容 |
| --- | --- |
| ウィンドウ・表示 | 画面サイズ、表示モード、フルスクリーン、ディスプレイの選択 |
| 描画 | 利用するバックエンド、同期、フレーム上限、描画解像度、品質、対応する描画機能の選択 |
| 音響 | 利用する出力、共通音量、音響システムの実行設定 |
| リソース | 資産ルート、読み込み方針、キャッシュ容量、読み込み用ワーカーの設定 |
| 共通の実行基盤 | 実行や物理システムに対する共通の既定値、容量や処理の管理設定 |
| 診断 | ログ、検証情報、デバッグ表示、計測の設定 |
| エンジン拡張のサービス | 登録済みプラグインが定義する実行設定 |

YAMLは実行方式を選ぶために使います。新しいRustの実装をインストールしたり、組み込まれていないコードを生成したりする役割は持ちません。

## 資産ルートと読み込み先

画像や音の所在は実行環境に関する情報なので、資産ルートをYAMLで設定します。以下は設定形式の設計例です。現在のエンジン設定がこの形式を読み込めるという意味ではありません。

```yaml
schema_version: 1

assets:
  root: "./assets"

window:
  width: 1280
  height: 720
  fullscreen: false

render:
  backend: auto
  vsync: true

diagnostics:
  log_level: info
```

`assets.root`が相対パスなら、読み込んだ設定ファイルのあるフォルダーを基準に解決する方針です。起動時の作業フォルダーが変わっても、同じ設定ファイルから同じ資産へ到達できるようにします。

ローダーへ渡す`ui/title.png`などのパスは、この資産ルートから解決します。作者はソースコードのあちこちへ`./assets`を重複して書く必要がなくなります。読み込んだ資産のキーと型付きハンドルは、マテリアル、表示、音などのAPIへつながります。

拡張モジュールの資産、複数ルート、パッケージへ格納した資産などを扱う場合は、ルートの登録と参照の規則をリソース設計で定めます。上の一つのフォルダーの例を、すべての配布方法を制限する規則にはしません。

## 描画機能の要求と実際の対応を分ける

例えば高度なライティングやレイトレーシングを選択する機能を導入する場合、次の三点を区別します。

1. **ビルドの対応**：必要な描画実装がCargoの構成に含まれているか。
2. **実行環境の対応**：使用するGPU、ドライバー、バックエンドが必要な能力を持つか。
3. **作者の希望**：実行設定でその機能を無効、可能なら使用、必須のどれとして要求するか。

設定で有効にしただけで、未実装の機能や非対応の環境を対応済みにしません。実行前に検証し、必須の機能が使えない場合は理由を示します。代替方式を許可する設定なら、使用した方式と切り替えの理由を確認できるようにします。

ここでのレイトレーシングは設定の分類を説明する例であり、実装済み機能や採用済みの出荷要件ではありません。

## Cargoとプラグイン登録の関係

Cargoのfeatureは条件付きコンパイルや任意の依存を扱う仕組みです。必要な実装が大きい、外部依存がある、配布対象によって実装を選ぶなどの場合に利用します。素材一つや入力アクション一つを、すべてCargo featureとして扱う設計にはしません。[Cargoのfeature](https://doc.rust-lang.org/cargo/reference/features.html)

外部拡張はCargoの依存として導入し、そのプラグインをRustのエンジンビルダーへ登録する形を基本にします。依存に追加しただけでは、その拡張を自動的に有効化したり、ゲームの処理へ登録したりしません。

プラグインが独自の実行設定を必要とする場合は、登録されたプラグインが設定項目の型と検証を担当します。YAMLの設定名から任意のコードを自動で探して実行する方式は、別の設計判断として扱います。

## YAMLとRustからの設定を統合する

エンジンは、組み込みの既定値、YAMLの明示指定、起動ビルダーの明示指定の順に設定を統合する方針です。Rust側で一部を上書きした場合、指定していない項目まで既定値へ戻らないよう、明示指定と未指定を区別します。

統合した設定は起動前に検証します。エラーには設定キー、問題の値、必要な対応を含めます。実行時に変更できる設定と再初期化が必要な設定を区別し、型付きAPIから変更できる条件を定めます。

エンジンの現在の設定と対応能力は、Sceneや独自システムから取得できるようにします。作者が設定ファイルを独自に再解析して状態を推測する必要がない設計にします。

## v1の設定schema

以下は実装対象の契約です。現在のコードが読み込める設定の一覧ではありません。省略時には既定値を使い、未知キーと無効値は起動時エラーにします。プラグインの設定も登録されたschemaで検証します。

| キー | 型・制約 | 既定値 |
| --- | --- | --- |
| `schema_version` | `u16`、対応版のみ | `1` |
| `window.width`, `window.height` | 正の整数、実行環境の上限以下 | `1280`, `720` |
| `window.fullscreen`, `window.resizable` | bool | `false`, `true` |
| `window.display` | 表示装置識別子、省略可 | OSの既定装置 |
| `render.backend` | `auto/vulkan/dx12/metal`、組込・環境能力を検証 | `auto` |
| `render.vsync` | bool | `true` |
| `render.frame_limit` | 正の整数、省略可 | 上限の明示指定なし |
| `render.resolution_scale` | 正の有限数、描画先上限を検証 | `1.0` |
| `render.scaling` | `fit/integer`。縦横比維持の拡大縮小、または整数倍率・中央clip | `fit` |
| `render.lighting` | `disabled/grid` | `grid` |
| `audio.master_volume` | `0.0..=1.0` | `1.0` |
| `audio.device` | 出力装置識別子、省略可 | OSの既定装置 |
| `audio.required` | bool。falseなら装置取得失敗を診断して無音で継続 | `false` |
| `assets.root` | 設定ファイル基準のパス | `./assets` |
| `assets.cache_mib` | 正の整数 | `256` |
| `assets.decode_workers` | `auto`または正の整数 | `auto` |
| `storage.root` | 設定ファイル基準のパス | `./saves` |
| `storage.keep_generations` | `3`以上の整数 | `3` |
| `simulation.step_hz` | 正の`u16`、profileに記録 | `60` |
| `simulation.system_workers` | `1..=64`または`auto`。並列実行を明示許可した独立Systemの同時worker上限 | `1` |
| `simulation.gravity` | 有限なcell/秒²の`{x, y}` | `{x: 0.0, y: 627.84}` |
| `streaming.auto_observer` | bool | `true` |
| `streaming.active_margin_chunks` | 非負整数 | `1` |
| `streaming.resident_margin_chunks` | active margin以上の整数 | `2` |
| `limits.active_chunks`, `limits.resident_chunks` | 正の整数、residentはactive以上 | `512`, `2048` |
| `limits.entities`, `limits.rigid_bodies` | 正の整数 | `65536`, `2048` |
| `limits.material_particles` | 正の整数 | `262144` |
| `limits.commands_per_tick`, `limits.jobs` | 正の整数 | `16384`, `4096` |
| `diagnostics.log_level` | `error/warn/info/debug/trace` | `info` |
| `diagnostics.metrics` | bool | 開発buildは`true`、配布buildは`false` |
| `plugins.<stable_key>` | 登録プラグインの型付きrecord | 登録schemaに従う |

重力は新しいWorldの既定値です。WorldBuilderの明示指定が優先され、プレイヤーの移動速度やジャンプ力の定義には使いません。64cellを物理backendの1mに変換する基準profileでは、上の重力は9.81m/秒²に対応します。単位変換は[データ設計](08_DATA_MODEL_AND_FORMATS.md)に従います。

ユーザーが変更した音量・表示設定は別のユーザー設定領域へ保存し、配布されたプロジェクト設定を上書きしません。ユーザー設定は許可された表示・音響項目だけへ適用し、Worldの正規設定や作者定義を変更しません。活動域とobserverの契約は[空間・活動設計](24_AI_NAVIGATION_AND_SPATIAL_ACTIVITY.md)を参照します。
